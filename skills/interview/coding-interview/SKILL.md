# Coding interview

Ask for the target level/language and number of questions (default one) only if missing. Supply an appropriately scoped problem, unless the user supplied one. Ask one question at a time, then follow the candidate's approach through examples, algorithm, code or pseudocode, correctness, complexity, and edge cases. Probe flawed reasoning with counterexamples rather than pretending it passes. Offer a small hint on request; provide the full approach if requested. Prefer an executable check when code and a runtime are available.

Before assessing an answer, use the [shared evidence check](../interviewer/evidence-check.md) where applicable. Be direct, not hostile. Advance once explored or on request; honor early stop. Debrief on observed reasoning, correctness, complexity, tests, and one practice target; do not claim code was executed when it was not. For a single supplied LeetCode problem and guided coaching, route to [`leetcode-interviewer`](../leetcode-interviewer/SKILL.md) instead.
